# UI 走查清单与重构记录

> 走查方式：在真实浏览器（Chromium，WebView2 同内核）里注入命令层 mock 跑起全部页面与状态，
> 逐个断点截图 + 用脚本量取对比度、字号、圆角、溢出、焦点、无障碍属性。所有结论都有实测数据，
> 不是"看代码猜"。测量脚本与场景配置留在 `.e2e/ui-audit/`（已被 .gitignore 忽略）。

断点：1440×900 / 1024×720（产品默认窗口）/ 800×600（Tauri minWidth×minHeight）/ 390×844（移动端）。
场景：默认多会话、空列表、单崩溃会话、命令报错、会话失联（gone）、解析跳过、启动恢复报错、慢加载。

## A. 布局与响应式

| # | 问题 | 实测证据 | 处理 |
| --- | --- | --- | --- |
| A1 | `.shell{min-width:800px}` + `body{overflow:hidden}`：窗口窄于 800 时界面被裁切且无法滚动 | 390 宽下 `scrollWidth=800`、内容右侧被切掉 | 去掉 min-width，改为真正的响应式骨架 |

## 约束遵守

- **没有改后端**：没动 `crates/`、`src-tauri/`、任何命令名、IPC 参数或返回值。
- **没有改功能设计**：路由（单页，无路由）、数据流、业务流程、交互语义全部保持。所有按钮仍然调用同一个回调，参数一致；轮询节奏（运行中 1s / 空闲 3s）、选中规则、表单载荷结构、图标缓存策略均未变。
- **结构变更只碰表现层**：
  - `AppList` 把「行容器 div[role=button] 内嵌 button」改为「覆盖层 button + 同级 button」——对外可点击区域、回调、`stopPropagation` 语义完全一致。
  - `AppForm` 引入 `Field` 包装，`id`/`name`/`props` 与提交载荷逐字段一致。
  - `SessionDetail` 抽出 `TabPanel`，条件渲染行为不变（只渲染当前面板）。
  - `Dialog` 替换原来的 `.modal-backdrop` 内联结构，取消/确认回调未改。
- **可审查、可回滚**：所有改动集中在 `src/`（组件与样式）以及新增的测试与文档；删除的只有 `src/styles.css` 一个文件（内容已按职责拆分到 5 个文件）。
